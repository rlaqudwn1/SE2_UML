# 다이어그램 모델 v1

구현 언어와 무관한 공통 인터페이스를 [JSON Schema](../schemas/diagram-document.schema.json)로 정의한다. 저장 파일은 UTF-8 JSON이며 `schemaVersion: "1.0"`, `kind`, `id`, `name`, `source`, `model`, `layout`, `styles`를 가진다. `kind`는 `class` 또는 `sequence`이며 이에 맞는 모델과 배치를 함께 사용한다. 알 수 없는 버전은 로드를 거부한다. 향후 버전 변경 시 명시적인 마이그레이션을 제공한다. 이 버전은 미배포 초안으로, 앞선 원문·스타일 없는 초안을 대체한다.

## 공통 규칙

- 모든 의미 요소는 문서 안에서 고유한 비어 있지 않은 문자열 `id`를 가진다. ID는 최초 생성 후 영속 저장하며 이름, 배열 위치, 좌표로 재생성하지 않는다. 클래스·참여자는 Mermaid 식별자를 ID로 사용하고 표시 이름은 분리한다. 식별자 자체 변경은 편집 트랜잭션에서 참조와 배치를 함께 갱신한다. Mermaid에 별도 자체 ID 문법을 추가하지 않는다. 멤버·관계·메시지는 파서가 이전 모델과 대응시켜 내부 ID를 유지한다. 중복 메시지 대응이 모호하면 기존 배치를 임의의 메시지에 붙이지 않고 진단한다.
- 참조는 표시 이름이 아닌 ID를 사용한다. ID의 고유성 및 참조 무결성은 로더에서 검증한다. JSON Schema는 구조와 값의 범위를 검증한다.
- `model`은 UML 의미만, `layout`은 사용자가 지정한 배치만 저장한다. 배치 배열은 부분적으로 존재할 수 있고 빈 배열도 유효하다. 누락한 요소만 자동 배치한다.
- 좌표와 간격은 확대 배율과 무관한 다이어그램 논리 단위다. 클래스 좌표는 좌측 상단이며 음수도 허용한다. `layout.sizes`는 사용자가 조절한 양수 width/height를 저장한다. 없는 크기는 텍스트를 담도록 렌더러가 계산한다. `layout.edges`의 waypoints는 source에서 target 순서의 중간 꺾임점이다. 빈 배열은 직선 경로 요청이다. 끝점은 노드 경계에서 계산하며 노드 이동 시 연결을 유지한다. 간선 이동은 중간점의 평행이동으로 표현한다. 끝점 자체의 수동 부착 위치는 후속 설계 대상이다.
- 이름 수정은 ID와 배치를 유지한다. 삭제 시 관련 배치와 참조를 함께 정리한다. 로더는 존재하지 않는 ID의 배치를 거부한다. 자동 정렬은 해당 문서의 배치 배열을 비워 의미 모델을 보존한다.
- 저장 시 의미와 배치를 하나의 문서로 기록한다. 다시 열면 배치를 우선 적용한다. 자동 계산 결과를 사용자 배치로 저장하지 않는다.

## 클래스 모델

`classes`는 클래스 또는 인터페이스(`kind`)를 담는다. 각 요소는 속성 `attributes`, 메서드 `methods`를 가지며 멤버도 안정적인 ID를 갖는다. 가시성은 `public`, `protected`, `private`, `package`다. 속성은 타입·정적 여부를, 메서드는 매개변수·반환 타입·정적/추상 여부를 기록한다. 타입은 현 단계에서 표시용 문자열이다.

`relationships`는 `association`, `aggregation`, `composition`, `inheritance`, `realization`, `dependency`를 지원한다. `source`와 `target`은 클래스 ID다. 상속·실체화는 구체 요소에서 부모·인터페이스로 향하고, 집합·합성은 전체에서 부분으로 향한다(다이아몬드는 source). 양 끝의 역할명과 다중성은 선택 사항이다. 다중성은 `1`, `0..1`, `*`, `1..*` 같은 표시 문자열이다. `navigable`은 연관 관계의 탐색 방향이며 `source`, `target`, `both`, `none` 중 하나다.

`layout.nodes`는 클래스별 `{ id, x, y }`를 저장한다. 동일 ID를 두 번 배치할 수 없다. 관계선은 저장된 중간점을 거쳐 양 끝 위치에서 다시 계산한다.

## 시퀀스 모델

`participants`는 `actor` 또는 `object`와 표시 이름을 가진다. 배열 순서가 초기 가로 배치 순서다. `messages` 배열 순서가 유일한 실행 순서다. 메시지는 `sync`, `async`, `reply` 중 하나이며 `from`, `to`는 참여자 ID다. 자기 자신에게 보내는 메시지도 허용한다. `replyTo`는 응답 메시지에서만 선택적으로 제공하며 반드시 앞선 호출을 참조하고 송수신 방향이 반대여야 한다.

`activations`는 참여자 ID와 시작/종료 메시지 ID로 활성 구간을 정의한다. 경계는 해당 메시지 이벤트를 포함하며 시작은 종료보다 늦을 수 없다. 경계 메시지는 해당 참여자가 보내거나 받는 메시지여야 한다. 같은 참여자의 구간은 분리 또는 완전 중첩만 허용하고 교차는 거부한다. 같은 경계의 중복 구간은 거부한다. 중첩 깊이와 화면 폭은 렌더러가 계산한다.

`layout.participants`는 `{ id, x }`만 저장한다. `layout.messageSpacing`은 `{ id, gapBefore }`를 저장한다. `gapBefore`는 이전 메시지(첫 메시지는 헤더 아래 기준선) 이후 추가할 음이 아닌 간격이다. 렌더러의 기본 간격에 더하므로 메시지 순서는 항상 유지된다. 메시지 드래그는 간격만 변경한다. 순서 변경은 의미 모델을 편집하는 별도 작업이다.

## 검증 및 예시

[클래스 예시](../examples/class-diagram.json)는 주문과 항목의 합성, 인터페이스 실체화, 의존 관계를 표현한다. [시퀀스 예시](../examples/sequence-diagram.json)는 주문 요청, 비동기 이벤트, 응답, 활성 구간을 표현한다. 두 예시 모두 일부 요소에만 배치를 지정해 새 요소의 자동 배치도 확인할 수 있다.

JSON Schema Draft 2020-12 호환 검증기로 파일 구조를 검사한 뒤, 위의 ID 고유성·참조·배치 대상 종류·실행 순서·활성 구간 규칙을 검사한다. 스키마만으로 참조 무결성이 보장되지는 않는다. `python scripts/validate_examples.py`로 검사한다(`python -m pip install -r requirements-dev.txt` 필요). 파서, 렌더러, 저장·복원 구현은 후속 기능의 범위다. 조건 분기·반복 프래그먼트, 참여자 생성/소멸은 현재 구조에서 아직 표현하지 못하므로, import 시 조용히 버리지 않고 미지원 진단을 반환해야 한다. 전체 Mermaid 지원을 완료했다고 간주하지 않는다.

## 원문·스타일·편집 계약

`source.language`는 `mermaid` 고정이며 `source.text`는 가져온 Mermaid 원문을 보존한다. JSON은 로컬 작업 파일 컨테이너이지 새 다이어그램 언어가 아니다. 의미 편집은 source와 model을 한 트랜잭션으로 갱신하고 검증 성공 시에만 확정한다. 문법 오류 입력은 편집기 임시 버퍼에 유지하고 마지막 정상 모델과 원문을 덮어쓰지 않는다. 로드 시 원문을 파싱해 모델과 일치하는지 검사해야 한다. 현 검증 스크립트는 Mermaid 파서를 포함하지 않는다.

Mermaid에는 두 종류에 공통으로 적용할 자유 좌표 저장 문법이 없으므로, **GUI 이동을 코드에도 반영한다는 FR-3의 충족 방식은 미결정**이다. 현재 제안은 의미 편집을 Mermaid에 반영하고 자유 배치를 JSON에 보존하는 것이다. 이는 저장·복원 계약이며, 좌표가 코드에 반영된다는 수락 기준의 구현 완료를 뜻하지 않는다. 고객/팀 합의 후 Mermaid 표준 주석을 이용한 메타데이터 또는 별도 배치 패널 등 대안을 결정한다. 자체 좌표 DSL은 추가하지 않는다.

`styles.elements`는 클래스·참여자에 대한 fill/stroke/textColor 오버라이드다. 지정하지 않으면 흰 배경·검은 선/문자를 사용한다. 흑백과 별도로 빨강(#EF4444), 파랑(#3B82F6), 초록(#22C55E), 노랑(#EAB308)을 기본 팔레트로 제공하는 설계다. PDF의 더 강한 '흑백 + 최소 4색' 조건을 따른다. 폰트는 문서 전체 고딕 계열(sans-serif), 단일 크기 최소 32로 정의한다. 실제 한글 고딕 폰트 번들링은 렌더러에서 보장해야 한다. 박스 크기를 늘려 텍스트를 담고 글자만 축소하지 않는다.

공통 서비스 인터페이스는 다음 계약을 따른다(언어 미정이므로 시그니처는 개념 표기).

| 인터페이스 | 입력 → 출력 및 보장 |
| --- | --- |
| Parser.parse | Mermaid 원문, 이전 정상 문서 → model 또는 위치 포함 diagnostics; 미지원 구문을 버리지 않음 |
| Editor.apply | 정상 문서, 단일 요소 편집 → 새 정상 문서; source/model/layout/styles를 원자적으로 갱신 |
| Layout.reconcile | 이전 배치, 새 model → 기존 수동 배치 보존 + 신규 노드만 자동 배치; 삭제된 참조 정리 |
| DocumentStore.save/load | 정상 문서 ↔ UTF-8 JSON 로컬 파일; 전체 구조 및 의미 검증 후 교체 |
| History.commit/undo | 정상 편집 전 스냅샷을 최대 5개 유지; undo가 source/model/layout/styles 전체 복원 |
| Renderer.render/export | 정상 문서 → 화면 또는 PNG/JPG; 수동 크기·경로·색상·폰트 반영 |

undo는 세션 메모리에서 관리하고 파일에는 이력을 넣지 않는다. 파일을 새로 열면 이력은 비운다(설계 제안). 드래그 중 매 프레임이 아니라 드래그 완료가 1단계이며 실패한 편집은 이력에 넣지 않는다. 자동 정렬도 undo 가능해야 한다. 다중 선택은 지원하지 않는다.

시퀀스 메시지 경로 편집은 이벤트의 순서와 기준 높이를 바꾸지 않으며, 꺾임점이 다른 이벤트의 순서를 암시하는 경우 편집기가 거부하거나 제한한다. 구체적인 제약과 스냅 기준점·허용 거리는 아직 미정이다.
