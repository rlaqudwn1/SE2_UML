# 클래스 팀의 다이어그램 모델 인터페이스 초안 — 김병주

작업 브랜치: `feat/diagram-model-kim-byeongju` (기준: `feat/diagram-model`).
병합 대상은 `feat/diagram-model`이며, 공통 계약을 두 팀이 확인한 뒤 모델 브랜치를 `dev`에 통합합니다.

## 조사 근거와 범위

[배치 알고리즘 조사 노트 (김병주)](https://app.notion.com/p/2-3ebc84b2acec813f9cb5e47eef7760eb)를 바탕으로 작성했습니다. 노트는 지정 Mermaid 커밋의 코드 조사이며 브라우저 실측은 하지 않았다고 명시합니다. 클래스의 자동 배치는 전체 그래프에 영향을 줄 수 있고, 사용자 좌표 보존은 별도 정책이 필요하다는 조사 결론을 설계에 반영했습니다. ELK INTERACTIVE의 위치 보존 효과는 검증되지 않았으므로 엔진을 확정하지 않습니다.

Java 사용은 사용자 결정입니다. Java 17 이상을 초안의 기준으로 삼아 `record`를 사용했습니다. 좌표 단위, 관계 방향, 저장 계약은 이번 초안의 제안이며 팀 합의 대상으로 구분합니다. 시퀀스 팀의 내부 모델은 이 브랜치에서 확정하지 않습니다.

## 인터페이스 구분

| 계약 | 책임 |
| --- | --- |
| `SemanticDiagram` | 다이어그램 종류와 의미 모델의 공통 진입점 |
| `LayoutState` | 다이어그램별 저장 배치의 공통 진입점 |
| `DiagramDocument<M, L>` | 의미 모델과 배치를 묶는 버전 1 문서; 종류 불일치 거부 |
| `ElementId` | 이름·선언 순서와 독립적인 내부 식별자 |
| `ClassDiagram` | 클래스·속성·메서드·관계의 의미 데이터 |
| `ClassLayout` | 클래스 ID별 사용자 지정 위치 |
| `ClassLayoutEngine` | 의미 모델·측정 크기·저장 위치를 최종 렌더링 데이터로 변환 |
| `DocumentCodec<M, L>` | 저장 형식으로 변환하고 복원하는 어댑터 계약 |

공통 계약은 `DiagramModel.java`, 클래스 전용 계약은 `ClassDiagram.java`, `ClassLayout.java`, `ClassLayoutEngine.java`에 정의했습니다. 외부 라이브러리에 의존하지 않습니다. 시퀀스 팀은 `SemanticDiagram`과 `LayoutState`를 각각 구현할 수 있으며 자유로운 x/y 좌표 저장을 강제받지 않습니다.

## 클래스 의미 모델

- 클래스: ID, 이름, 종류(일반/추상/인터페이스/열거형), 스테레오타입, 속성, 메서드.
- 속성: ID, 이름, 타입, 접근 범위, 정적 여부.
- 메서드: ID, 이름, 매개변수, 반환 타입, 접근 범위, 정적·추상 여부.
- 관계: ID, 종류, 양 끝 클래스 ID, 역할·다중성, 라벨, 탐색 방향.

관계는 연관·의존·일반화·실체화·집합·합성을 구분합니다. 일반화는 자식에서 부모, 실체화는 구현체에서 인터페이스, 의존은 의존하는 쪽에서 공급하는 쪽을 향합니다. 집합·합성은 전체를 source, 부분을 target으로 정의하며 다이아몬드는 source에 표시합니다. 연관의 화살표는 별도의 탐색 가능 여부로 정합니다.

역할·다중성을 지정하지 않았으면 빈 문자열을 사용합니다. 타입과 다중성은 우선 문자열로 표현하며, 지원 문법과 타입 검사는 파서 단계에서 확정합니다. 패키지·제네릭·노트·관계선 수동 편집은 이번 최소 계약의 범위에 포함하지 않습니다.

## 좌표와 배치 엔진 계약

1. 좌표는 화면 확대·스크롤에 독립적인 월드 좌표입니다. x는 오른쪽, y는 아래로 증가하고 음수 좌표도 허용합니다.
2. 저장 위치는 클래스 박스의 왼쪽 위 절대 좌표입니다. 자동 배치 결과에 더하는 오프셋으로 해석하지 않습니다.
3. `manualPositions`에 있는 클래스는 수동 위치를 유지합니다. 없는 클래스만 자동 배치 대상으로 삼습니다.
4. 드래그는 `withPosition(id, point)`로 새 배치를 만듭니다. UML 의미 모델은 변경하지 않습니다.
5. 이름 수정·요소 추가 후에도 같은 요소의 ID와 수동 위치를 유지합니다. 파서는 이름만으로 ID를 재생성하지 않아야 합니다.
6. 삭제한 클래스의 위치는 문서 갱신 시 제거합니다. 개별 자동 배치 복귀는 `withoutPosition`, 전체 초기화는 `automatic`으로 표현합니다.
7. 렌더러가 실제 폰트로 측정한 클래스 크기를 `measuredSizes`에 제공합니다. 배치 엔진은 모든 클래스의 크기를 받아야 합니다.
8. 엔진은 최종 노드 위치를 결정한 뒤 관계선을 다시 계산하고, 노드·관계선·라벨을 포함하는 경계를 반환해야 합니다.
9. 겹침이 발생해도 수동 위치를 몰래 변경하지 않습니다. 경고를 반환하고 자동 정렬은 명시적인 사용자 동작으로 처리합니다.

`ClassLayoutEngine.Result`의 노드 박스·관계선 경로·전체 경계는 계산 결과입니다. 영구 저장할 사용자 위치와 구분합니다. 엔진 구현과 실제 관계선·라벨 겹침 검증은 후속 브랜치에서 진행합니다. 기존 자동 배치 요소의 위치 안정성은 이번 계약에서 보장하지 않습니다.

## 저장·복원과 검증 책임

문서에는 의미 모델과 배치를 함께 저장합니다. 실제 저장 위치(별도 파일/메타데이터/DB)와 JSON 라이브러리는 미정입니다. `DocumentCodec` 구현은 다음 조건을 만족해야 합니다.

- round trip 후 ID와 수동 좌표가 동일해야 합니다.
- 지원하지 않는 문서 버전과 종류 불일치를 거부해야 합니다.
- ID 중복, 없는 클래스에 대한 관계·좌표 참조, null 필드와 잘못된 이름·다중성을 검증해야 합니다.
- 임의 텍스트 재입력 시 기존 ID를 연결하는 정책을 파서·편집기와 합의해야 합니다. 이름 변경만 보고 동일성을 확정하기 어려운 경우 자동 추정 대신 명시적인 매핑이 필요합니다.

현재 record는 컬렉션 복사, ID 공백, 좌표·크기의 유효성, 문서 버전·종류를 검증합니다. 참조 무결성과 UML 문법의 전체 검증기, codec 구현은 아직 없습니다.

## 실행 가능한 모델 예시와 검증

`ModelContractCheck.java`에는 클래스 생성 → 음수 좌표로 이동 → 이름 수정·새 클래스 추가 → 배치 데이터 재구성 → 자동 배치 복귀 예시가 있습니다. 원본 모델의 불변성, 위치 유지, 새 요소의 자동 배치 대상 여부, 잘못된 좌표·크기·문서 거부를 확인합니다. 파일 저장·재읽기와 렌더링을 검증하는 테스트는 아닙니다.

Java 17 이상에서 저장소 루트에서 실행합니다.

```bash
bash scripts/check-model.sh
```

- 텍스트 수정 시 ID 연결과 좌표 메타데이터를 어떻게 유지할 것인가?
- 실제 클래스 배치 엔진과 렌더링 환경은 무엇인가?
- 초기 지원 UML 문법과 추가할 요소 범위는 무엇인가?
