# SE2_UML

Mermaid처럼 텍스트로 클래스·시퀀스 다이어그램을 정의하고, 화면에서 이동한 요소의 위치를 저장·복원하는 UML 도구를 개발합니다.

현재는 Java 기반 인터페이스를 정의하는 단계입니다. 김병주의 담당 범위는 **시퀀스 다이어그램의 배치 알고리즘 인터페이스**입니다. 문법과 의미 데이터 구조는 다른 팀원이 정의하며, 이 작업에서는 변경하지 않습니다. 배치 계약과 검증 방법은 [시퀀스 배치 인터페이스](docs/SEQUENCE_LAYOUT_CONTRACT.md)에 정리했습니다. 아래 내용은 전체 프로젝트의 개발 전략이며 개인 작업 범위와 구분합니다.

[HTML 인터페이스 설명](docs/sequence-layout-interface.html)을 브라우저에서 열면 입력·출력 구조와 좌표 제약 예시를 시각적으로 확인할 수 있습니다. 외부 의존성 없이 파일 자체를 열어 사용할 수 있습니다.

[코드와 설계 근거](docs/INTERFACE_DESIGN_RATIONALE.md)에는 실제 Java 발췌, 선택 이유와 대안, Mermaid·Java 공식 레퍼런스, 구현 상태를 함께 정리했습니다.

## 개발 전략

**공통 모델의 인터페이스를 먼저 합의하고, 클래스·시퀀스의 구현을 나눕니다.** 공통 모델을 설계할 때부터 두 다이어그램의 예시 데이터를 함께 만들어 요구사항을 확인합니다.

공통으로 정의할 항목은 문서 버전, 다이어그램 종류, 안정적인 요소 ID, 배치 정보, 저장 형식입니다. 클래스의 속성·메서드·관계와 시퀀스의 참여자·메시지·실행 순서·활성 구간은 각각 별도의 모델로 정의합니다.

```text
DiagramDocument
├─ 공통: 버전, 다이어그램 종류, 요소 ID, 배치 정보
├─ ClassDiagram: 클래스, 속성, 메서드, 관계
└─ SequenceDiagram: 참여자, 메시지, 실행 순서, 활성 구간
```

모델과 배치의 공통 규칙을 완성한 뒤 클래스 다이어그램에서 텍스트 입력, 렌더링, 드래그, 저장·복원 흐름을 먼저 구현합니다. 이후 시퀀스 다이어그램에 필요한 편집 제약을 추가합니다. 구현 언어는 Java이며, 프로젝트의 안정 버전 기준은 **Java 25 LTS**입니다([공식 안내](https://www.oracle.com/java/technologies/downloads/)). Preview 기능은 사용하지 않습니다. 프레임워크와 렌더링 환경은 아직 정하지 않았습니다.

## 좌표 관리 전략

UML의 의미 데이터와 화면 배치 데이터를 분리합니다. 사용자가 요소를 이동하면 해당 ID에 연결된 배치 정보를 갱신하고, 다시 열었을 때 저장된 위치를 적용합니다.

| 상황 | 동작 |
| --- | --- |
| 처음 표시하는 요소 | 저장된 위치가 없으면 자동 배치 |
| 요소 드래그 | 사용자 위치를 갱신하고 연결선을 다시 계산 |
| 저장 후 다시 열기 | 저장된 사용자 위치를 우선 적용 |
| 이름이나 텍스트 수정 | 같은 요소의 ID와 기존 위치 유지 |
| 새로운 요소 추가 | 기존 배치를 유지하고 새 요소만 자동 배치 |
| 자동 정렬 실행 | 사용자 배치를 초기화하고 다시 배치 |

클래스는 자유롭게 이동할 수 있도록 합니다. 시퀀스는 참여자의 가로 이동과 메시지 간격 조절을 우선 지원하며, 실행 순서는 의미 모델에서 관리합니다. 메시지의 세로 좌표 이동만으로 실행 순서가 바뀌지 않도록 합니다.

## 브랜치 구성

```text
main                              검증된 배포 버전, GitHub 기본 브랜치
dev                               기능 통합 및 검증
├─ feat/diagram-model             공통 인터페이스와 다이어그램별 모델
├─ feat/layout-core               좌표 관리·저장·복원
├─ feat/class-parser              텍스트 → 클래스 모델
├─ feat/class-renderer            클래스·관계선 렌더링
├─ feat/class-editor              클래스 이동·관계선 갱신
├─ feat/sequence-parser           텍스트 → 시퀀스 모델
├─ feat/sequence-renderer         참여자·메시지·활성 구간 렌더링
└─ feat/sequence-editor           참여자 이동·메시지 간격 편집
```

기본 브랜치는 `main`, `dev`, `feat/diagram-model`입니다. 김병주의 시퀀스 배치 알고리즘 인터페이스 작업은 모델 브랜치에서 분기한 `feat/diagram-model-kim-byeongju`에서 진행하며, PR 대상은 `feat/diagram-model`입니다. 문법·의미 데이터 구조 담당자와 접점 계약을 합의한 뒤 `dev`에 통합합니다. 나머지 기능 브랜치는 선행 작업을 `dev`에 병합한 후 최신 `dev`에서 생성합니다. 위 트리는 역할 구분이며 모든 기능 브랜치를 미리 생성하지 않습니다.

## 개발 순서와 완료 기준

| 순서 | 브랜치 | 완료 기준 |
| --- | --- | --- |
| 1 | `feat/diagram-model` | 공통 인터페이스, 클래스·시퀀스별 모델, 두 종류의 예시 데이터 정의 |
| 2 | `feat/layout-core` | 사용자 위치 우선 적용, 저장·복원, 자동 정렬 규칙 구현 |
| 3 | `feat/class-parser` | 텍스트를 클래스 모델로 변환 |
| 4 | `feat/class-renderer` | 클래스와 관계선을 화면에 표시 |
| 5 | `feat/class-editor` | 이동한 위치에 관계선을 갱신하고, 저장 후 다시 열어도 위치 유지 |
| 6 | `feat/sequence-parser` | 텍스트를 시퀀스 모델로 변환 |
| 7 | `feat/sequence-renderer` | 참여자·메시지·활성 구간을 화면에 표시 |
| 8 | `feat/sequence-editor` | 실행 순서를 유지하면서 참여자 위치와 메시지 간격 편집 |

## 병합 규칙

팀별 인터페이스가 어떤 의도로 데이터를 주고받는지는 [인터페이스 연결도와 통합 절차](docs/INTERFACE_INTEGRATION.md)로 함께 확인합니다. `dev` 통합 시 입력·출력 예시, 호출 흐름, 좌표·순서 의미와 충돌 처리 방식을 시각화하며 검토합니다.

1. 선행 기능이 병합된 최신 `dev`에서 기능 브랜치를 만듭니다.
2. 기능 구현과 해당 동작 검증을 완료하고 `dev` 대상 PR을 만듭니다.
3. 병합이 끝난 기능 브랜치는 삭제합니다.
4. `dev`에서 통합 동작을 검증한 뒤 `main` 대상 PR로 배포 버전을 반영합니다.

일반 버그 수정은 최신 `dev`에서 `fix/<문제명>` 브랜치를 만듭니다. 배포 버전의 긴급 수정은 `main`에서 시작하고 결과를 `dev`에도 반영합니다.

자세한 작업 명령과 운영 규칙은 [BRANCHING.md](BRANCHING.md)를 참고하세요.
